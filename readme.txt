Create multilingual WordPress content, translate with dedicated APIs or popular AI models, edit language versions in Gutenberg, localize media, and cache HTML files.

== Description ==

LocalizePilot creates language-prefixed versions of WordPress posts and pages while keeping the original page path. Automatic translations can be generated through TranslateX, Google Cloud Translation, OpenAI, Google Gemini, Anthropic Claude, Kimi, DeepSeek, Mistral AI, Groq, or OpenRouter.

Every translated post or page is stored as a linked WordPress translation record. Editors can correct the title, excerpt, blocks, links, and media in Gutenberg without losing their work when cache files are cleared.

= Gutenberg translation workflow =

* Open an existing post or page.
* Use the LocalizePilot panel to create a language version.
* LocalizePilot generates the initial title, excerpt, and block content with the selected provider.
* Edit the translated blocks with Gutenberg.
* Choose a translated featured image or replace media inside translated blocks.
* Set the translation to Automatic, Edited, Reviewed, or Needs update.
* Save the translation to refresh its HTML snapshot and rendered-page cache.

= Translation providers =

* TranslateX
* Google Cloud Translation Basic v2
* OpenAI API for ChatGPT models
* Google Gemini API
* Anthropic Claude API
* Kimi API by Moonshot AI
* DeepSeek API
* Mistral AI API
* Groq API
* OpenRouter API

AI providers support editable model IDs, translation style, temperature, maximum output tokens, custom localization instructions, and an optional fallback provider.

= Translation statuses =

* Automatic: generated by the selected provider.
* Edited: changed by a WordPress editor in Gutenberg.
* Reviewed: manually checked and approved.
* Needs update: the original post or page changed after translation.

= Main features =

* Gutenberg-editable translations for posts and pages
* Dedicated translation APIs and popular AI translation providers
* Optional fallback provider when the primary API fails
* Faithful, natural, marketing, and formal AI translation styles

* No frontend JavaScript required for translation
* No WordPress transients used for translated HTML

= File storage =

Gutenberg translation content is exported to:

`wp-content/cache/localizepilot/{post-id}_{language}.html`

Complete rendered pages are cached separately at:

`wp-content/cache/localizepilot/pages/{post-id}_{language}.html`

The WordPress translation record is the source of truth. Cache files can be deleted and regenerated without deleting manual corrections.

== Installation ==

1. Upload the plugin ZIP from Plugins > Add New > Upload Plugin.
2. Activate LocalizePilot.
3. Open LocalizePilot in the WordPress admin menu.
4. Select a translation provider and enter its API key.
5. For an AI provider, confirm the model ID and optional AI instructions.
6. Select target languages and save settings.
7. Go to Settings > Permalinks and click Save Changes if language-prefixed URLs return 404.
8. Edit a post or page and create a translation from the LocalizePilot panel.

== Frequently Asked Questions ==


= How can I display the language switcher inside content or a template? =

Use `[localizepilot_switcher]` for the global design, or add overrides such as `[localizepilot_switcher style="inline" labels="native" alignment="center"]`. In the block editor, insert the LocalizePilot Language Switcher block and configure it from the block sidebar.

= Can I use ChatGPT to translate WordPress content? =

Yes. Select OpenAI, enter an OpenAI API key and model ID, and save the settings. A ChatGPT website subscription is separate from API access.

= Can I use Gemini, Claude, Kimi, or DeepSeek? =

Yes. Each supported provider has its own API-key and model settings. Provider availability, billing, models, quotas, and regional restrictions are controlled by that provider.

= Can I correct an automatic translation with Gutenberg? =

Yes. Every post and page translation is stored as a Gutenberg-editable WordPress record.

= Will clearing the cache delete my corrections? =

No. Manual corrections are stored in the WordPress database. HTML files are generated snapshots and caches.

= What does the fallback provider do? =

If the primary provider returns an error, LocalizePilot can retry the same translation batch with the selected fallback provider. The fallback provider also requires a configured API key.

= Are AI translations always accurate? =

No. Machine and AI translations can contain errors. Review important legal, medical, financial, product, and marketing content before publishing.

= Does LocalizePilot send analytics to ThemeDev? =

No. LocalizePilot does not send plugin analytics or telemetry to ThemeDev.

== External services ==

LocalizePilot sends website text to the provider selected by a WordPress administrator only when a translation must be generated, tested, or refreshed. Requests may include titles, excerpts, block text, visible page text, supported HTML attributes, source and target language codes, model settings, and custom translation instructions. API keys are sent only to the selected provider.
